## 3. Severity Guide

- **Critical:** Core POS operation is unavailable or data integrity is seriously at risk.
- **High:** Important functionality such as order completion, payment handling, or inventory updates is incorrect.
- **Medium:** A feature works incorrectly in a limited scenario but a workaround exists.
- **Low:** Minor display, usability, or non-blocking issue.

## 4. Verification and Fix Tracking

For each confirmed issue, record:

1. A reproducible description and the relevant test or steps.
2. The affected component or backend module.
3. The fix commit, if a fix is made.
4. The retest command and result.
5. Evidence showing the retest outcome.

Do not mark an issue fixed until the relevant retest passes. If no defects are found, record which tests were run and state that no defects were observed within that test scope; do not claim the entire application is bug-free.
