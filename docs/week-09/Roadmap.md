## 3. Final Demo Promise

SmartServe POS demonstrates a point-of-sale workflow for a small food or beverage business.

The main workflow is:

1. Select menu items and quantities.
2. Calculate the order total using saved menu prices.
3. Create an order and process a simulated payment.
4. Record the payment as paid.
5. Deduct the required ingredients from inventory.
6. Allow the owner to review orders and inventory information.

The objective is to demonstrate that ordering, payment, receipt generation, and inventory management work together.

## 5. Lessons and Technical Considerations

- Inventory deduction should happen only once for a paid order.
- Recipe quantities must be converted consistently when inventory and recipe units differ.
- Order records should preserve the item name and price used when the order was created.
- Backend tests should verify business rules, not only API responses.
- Evidence should clearly distinguish automated checks, independent testing, and live application screenshots.

## 9. Evidence Submission Guidelines

For every important feature, preserve:

- A short explanation of what the feature demonstrates.
- A screenshot or test output showing the result.
- A direct GitHub link to the evidence.
- Relevant code, test, or implementation references.
- The date and environment in which the evidence was generated.
- Clear identification of automated testing versus independent teammate testing.

Do not describe historical failed checks as passing results. Keep earlier evidence as part of the development history and use the latest verified results for final-demo claims.
