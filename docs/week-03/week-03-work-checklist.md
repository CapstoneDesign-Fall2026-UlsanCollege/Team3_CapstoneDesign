## Our stretch target

Choose at least three stretch items from at least two sections, or propose an equivalent extension. Explain why these choices matter:

> We selected stretch items that improve both the product direction and the technical readiness of SmartServe. These activities help us identify the main user outcome, reduce technical uncertainty, prepare a fallback version of the vertical slice, clarify dependencies, and make important decisions traceable to evidence. This reduces the risk of beginning implementation without a clear scope or understanding of the main technical dependencies.

### Selected stretch items

1. **One-sentence problem statement** — keeps the first implementation focused on the actual restaurant POS problem.
2. **Single user outcome** — gives the team a clear result that the first build must demonstrate.
3. **Riskiest assumption and cheap test** — allows important technical assumptions to be tested before major implementation work.
4. **Smaller fallback version of the candidate slice** — provides a reduced path that can still demonstrate the core order workflow if the full slice is delayed.
5. **Map dependencies between the first three Issues** — helps identify blockers before implementation begins.
6. **AI-use note / outside-material attribution** — makes the development process transparent and documents how external or generated material was reviewed.
