## Communication and Meetings

* **Main communication channel:** Messenger group chat
* **Normal response expectation:** Every member should respond within 24 hours.
* **Regular meeting or work time:** The team will mainly meet and work together in person at college.
* **Emergency communication:** If an urgent matter cannot wait for a Messenger response, members may call each other using the phone numbers shared within the team.
* **Additional coordination:** General discussions, progress updates, questions, and task coordination will take place through Messenger.
* **Recording decisions:** Important decisions, assigned tasks, bugs, and project changes will be recorded in GitHub Issues.
* **Absence or delayed work:** A member who cannot attend a meeting or complete an assigned task on time should notify the group through Messenger as early as possible.

## How We Work

* We create or update a GitHub Issue before beginning significant work.
* Every task should have a clear owner, expected deadline, and small Definition of Done.
* Team members regularly update the status of their assigned Issues.
* Developers work on separate branches instead of making major changes directly to the `main` branch.
* Substantial code changes are submitted through pull requests and reviewed before merging.
* Documentation, designs, test results, screenshots, research, and other evidence are uploaded or linked through GitHub.
* Non-coding members support the project through research, design, documentation, test preparation, manual testing, and presentation work.
* We keep the first version realistic and avoid adding features that cannot be completed within the project schedule.
* We give feedback about the work, not the person, and assume good intent.
* We follow the course Project Work Policy for privacy, attribution, academic integrity, and responsible AI use.

## GitHub Workflow

1. Create a GitHub Issue describing the task.
2. Assign the Issue to the responsible team member.
3. Add a clear Definition of Done and expected deadline.
4. Create a separate branch for coding or major document changes.
5. Complete the assigned work and test it.
6. Commit changes using a clear and meaningful commit message.
7. Open a pull request and link the related Issue.
8. Ask at least one team member to review the work.
9. Address any feedback before merging.
10. Merge the pull request and close the related Issue.

## Definition of Done

A task is considered complete when:

1. The agreed requirement has been implemented or documented.
2. The assigned member has checked and tested the work.
3. Relevant code, documents, screenshots, research, or other evidence have been added or linked.
4. Known limitations and unresolved problems have been recorded.
5. Another team member has reviewed the work when appropriate.
6. The related GitHub Issue has been updated or closed.

## If Work or Communication Breaks Down

1. Raise the concern privately and respectfully with the relevant teammate as early as possible.
2. Clearly identify the missed, delayed, or blocked task and explain how it affects the project.
3. Record the problem, available evidence, and next action in the relevant GitHub Issue or team note.
4. Agree on a realistic recovery plan, including a new deadline or task owner if necessary.
5. Review the recovery plan during the next team meeting.
6. If the problem remains unresolved or cannot be handled safely within the team, contact the instructor through the course-designated channel and provide the relevant GitHub links.
